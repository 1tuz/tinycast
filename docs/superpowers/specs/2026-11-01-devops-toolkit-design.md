# DevOps Toolkit Design

**Статус:** одобрено пользователем
**Объём:** раздел 11 `ROADMAP.md`, пункты 11.1–11.7, дополнительно 11.9 и KubeLens handoff из OMP
**Публикация:** отдельная ветка в `1tuz/tinycast`; `main` не изменять

## Цель

Добавить локальный DevOps toolkit в Tinycast. Он должен работать с установленными CLI и конфигурацией пользователя. Tinycast не хранит токены и не запускает команды без явного действия пользователя.

## Исходное состояние форка

- Базовая ветка — чистый `fork/main`; локальные незакоммиченные удаления из другого checkout сюда не переносятся.
- В Quick Actions уже есть 15 старых действий. JWT, CIDR, Kubernetes Secret, YAML ↔ JSON и Explain cron добавляются в рамках этой работы.
- `ShellCommandRunner.stream`, `TerminalLogView` и отмена процесса уже существуют и должны использоваться нативными долгими операциями.
- В extension runtime уже есть частичная async-обвязка для spawn, а menu-bar команды, менеджер и status item частично реализованы. Требуется довести потоки, stdin, владение процессами и постоянную runtime-сессию до требований 11.7.
- Workflows пока запускают только встроенные команды.
- Репозиторий требует Swift 6, macOS 26+, нулевые новые Swift-зависимости и отдельные standalone harnesses; XcodeGen включает новые Swift-файлы из `Tinycast/` автоматически.

## Архитектурное решение

Нативный код отвечает за Kubernetes, Ansible и процессы, которым нужен потоковый вывод, управление жизненным циклом или подтверждение. Используются `ShellCommandRunner`, `TerminalLogView` и существующий app-level coordinator.

Короткие команды «получить список → выполнить действие» остаются TypeScript/Raycast extensions. Они используют существующий extension host. Для них не добавляется отдельный сетевой backend.

Потоковый `child_process.spawn`, `menu-bar` extensions и пользовательские команды в Workflows — отдельные изменения платформы. В форке уже есть частичный async spawn и нативные status items; задача — завершить bidirectional I/O, процессный lifecycle и постоянную runtime-сессию, а не добавлять второй рендерер.

Новые внешние зависимости не добавляются. Для `kubectl get secret -o yaml` реализуется документированный блоковый YAML subset с JSON-совместимыми значениями; неподдерживаемые YAML конструкции явно отклоняются. Полный YAML 1.2 parser не заявляется. Cron parser поддерживает стандартные пять полей и не исполняет расписание.

## Компоненты и поведение

### 11.1 Quick Actions

Добавить пять локальных Developer Utilities: Decode JWT, Calculate CIDR, Decode Kubernetes Secret, YAML ↔ JSON и Explain cron.

- JWT принимает Bearer-токен или сырой compact token, декодирует header и payload, переводит `iat`/`nbf`/`exp` в UTC и всегда сообщает `Signature not verified`.
- CIDR вычисляет IPv4 network, netmask, wildcard, broadcast, диапазон и число хостов; `/31` и `/32` соответствуют RFC 3021, `/0` не переполняет счётчики.
- Kubernetes Secret принимает JSON или поддерживаемый блоковый YAML из `kubectl get secret -o json|yaml`, декодирует `data` локально, сохраняет многострочные UTF-8 данные блоками и обозначает бинарные значения как `<N bytes binary>`.
- YAML ↔ JSON принимает один документ и переводит JSON-совместимые скаляры, массивы и объекты. Ключи объектов должны быть строками. Несколько документов и значения, которые нельзя представить в JSON, дают понятную ошибку.
- Cron принимает пять полей: минута, час, день месяца, месяц, день недели. Поддерживаются `*`, списки, диапазоны и шаги. Невалидные поля отклоняются.
- Оба действия работают локально, не требуют AI и не отправляют данные наружу.

### 11.2 Kube Context Guard

Добавить отдельную выключенную по умолчанию функцию. Пока она выключена, Tinycast не читает kubeconfig.

- При включении прочитать стандартный путь и значение `KUBECONFIG`; поддержать несколько файлов с приоритетом, совместимым с kubectl.
- Парсер возвращает контексты, namespace, текущий контекст и данные, нужные для показа имени кластера. Не хранить токены или содержимое сертификатов в модели UI.
- Экран и menu bar показывают выбранный контекст и namespace. Переключение меняет контекст Tinycast; команды передают выбранный `--context` явно и не меняют глобальный `current-context` пользователя.
- Пользователь настраивает точный список production contexts. Проверка выполняется по имени контекста и повторяется в сервисе непосредственно перед запуском действия.
- Для production contexts мутирующие действия скрыты и отклоняются сервисом. Одна лишь UI-проверка не считается защитой.

Tinycast не меняет глобальный `current-context`. Выбранный контекст действует внутри Tinycast, а каждая команда получает его через `--context`.

### 11.3 Pods / Logs

- Получать поды как JSON с явными `--context` и `--namespace`.
- Показывать статус, контейнеры и фильтр проблемных состояний, включая Pending и CrashLoopBackOff.
- Действия: открыть потоковые логи, describe, скопировать имя и открыть интерактивный exec в Terminal.
- `rollout restart` доступен только для непрод-контекста и после подтверждения. Сервис повторно проверяет контекст перед запуском.
- Потоковые логи используют `ShellCommandRunner.stream`; остановка закрывает процесс и окно.

### 11.4 Port-forward / Service Manager

Добавить менеджер app-scoped процессов для `kubectl port-forward`, `vault proxy` и `ssh -L`.

- Аргументы передаются массивом; команды не собираются в shell-строку.
- Активные сессии видны в menu bar с целью, портами и состоянием.
- Пользователь может остановить отдельную сессию. При выходе из Tinycast все сессии останавливаются.
- При неожиданном завершении повторять запуск с ограниченной экспоненциальной задержкой. Ручная остановка запрещает перезапуск. Ошибки и частый цикл рестартов показываются пользователю.

### 11.5 Ansible Runner

- Найти `ansible-inventory`, `ansible-playbook` и `ansible` через существующий поиск исполняемых файлов.
- Читать JSON из stdout `ansible-inventory --list`; показывать группы и хосты.
- Пользователь выбирает inventory и playbook, затем задаёт limit и tags. Передавать их отдельными аргументами.
- Обычный запуск всегда добавляет `--check --diff`. Реальный запуск является отдельным действием с подтверждением.
- Показывать потоковый вывод и позволять отмену. Хранить локальную историю с путями, аргументами, временем и кодом завершения; не сохранять полный stdout/stderr.
- Добавить SSH и ad-hoc ping для выбранного хоста.

### 11.6 Raycast extensions

Добавить шесть коротких расширений, используя существующий manifest/API/extension host. Исходники находятся в `Extensions/DevOps/`; сборка создаёт готовые пакеты в app resources. Extension Store показывает их в локальной коллекции и устанавливает по явному действию через существующий `ExtensionManager.install(from:)`. Установка не требует сети. Удалённое расширение остаётся доступным в коллекции.

- **Git Worktrees:** список проектов в выбранных пользователем корнях; ветка, dirty и ahead/behind. Создание по Jira key. Открытие MR через `glab`. Удаление только чистого слитого worktree и только после подтверждения. Выбор корней вместо безусловного обхода `~/Documents/projects` — намеренная граница доступа.
- **Jira Key Actions:** распознавание выделенного `DO-NNNN` при наличии Accessibility permission, с ручным вводом как fallback; переход по настроенному Jira URL, копирование имени ветки и переход к локальному worktree/MR при наличии.
- **Compose Projects:** поиск проектов по Compose labels; up/down/restart и переключение выбранного Docker context. Команды получают `--context` явно и не меняют глобальный Docker context. Операции, которые останавливают или удаляют ресурсы, требуют подтверждения; `down` не удаляет volumes.
- **Helm Releases:** список релизов, history и просмотр values по явному запросу; не сохранять values. Rollback доступен только для непрод-контекста и требует подтверждения.
- **Vault Lookup:** запуск `vault kv get -format=json`, выбор поля и копирование значения без показа. Копировать через `NSPasteboard` с `ClipboardManager.internalType`; не вызывать обычный clipboard ingest path и не писать секрет в лог, UI state, историю или clipboard history Tinycast.
- **SSH Hosts:** показывать только Host aliases из пользовательского `~/.ssh/config` и Ansible inventory; раскрывать итоговые настройки через `ssh -G <alias>`, открывать выбранный alias в Terminal. Не читать приватные ключи.

Интеграции проверяют наличие CLI и показывают действие по установке/настройке, но не устанавливают программы автоматически. Для Git projects и Jira base URL пользователь задаёт разрешённые корни и URL.

### 11.7 Доработки платформы

#### Потоковый spawn

Сделать `child_process.spawn` Node-совместимым потоковым API: stdout/stderr data events, stdin write/end, exit/error/close и kill. Текущий внутренний код spawn не вызывает; `exec` и `execFile` сохраняют буферизованный контракт. События идут через асинхронный двунаправленный канал между `ExtensionHostBridge` и JS runtime. Потоковый вывод не накапливается целиком в памяти. Завершение extension, отключение extension и выход из Tinycast останавливают принадлежащие им процессы.

Сохранить существующую совместимость коротких buffered spawn-вызовов. Для новых потоков передавать executable и args отдельно, применять таймауты и лимиты очереди событий. Shell interpolation не добавлять.

#### Menu-bar extensions

Для каждой включённой `menu-bar` команды держать один runtime между обновлениями. Преобразовывать её дерево `MenuBarExtra` в нативный status item; refresh вызывает команду в том же runtime, а клики направляются через существующий extension action dispatcher. Refresh interval ограничивается manifest policy; выключение или ошибка extension останавливают процессы и удаляют status item.

#### Пользовательские команды в Workflows

Расширить модель Workflow типом действия для выбранной Custom Command и позиционных аргументов. Использовать существующие trigger и `ShellCommandRunner`. Для команды с `requiresConfirmation` спрашивать подтверждение при каждом срабатывании; не запускать такую команду скрыто из clipboard/file/time trigger. История не сохраняет секретный вывод. Триггеры остаются активны только пока запущен Tinycast.

### 11.9 Быстрые DevOps-действия

Добавить шесть интеграций, опираясь на существующие палитру, калькулятор, Quick Actions, clipboard, snippets и launcher ranking.

- **Карточки в launcher:** распознавать IPv4 CIDR, Jira key и JWT в запросе. CIDR и JWT показывают локально вычисленный результат. JWT явно помечен как неподписанный: это decode, не проверка подписи. Jira открывается только через настроенный пользователем base URL.
- **Kubernetes quantities в калькуляторе:** поддержать `Ki/Mi/Gi/Ti` как бинарные байтовые единицы и CPU millicores в выражениях с явным `cpu`, включая `512Mi in GiB`, `1500m cpu` и `2Gi * 3`. Обычное `m` без `cpu` сохраняет текущее значение метра.
- **Fallback Quick Actions:** если чтение выделения не дало текст, после явного запуска Quick Action предложить использовать текущий clipboard text. Не читать clipboard в фоне и не передавать clipboard содержимое AI-действиям без отдельного действия пользователя.
- **Clipboard badges/actions:** распознавать JWT, Kubernetes YAML и IPv4/CIDR в уже сохранённом текстовом элементе и показывать локальное действие. Не перечитывать NSPasteboard, не добавлять сетевую обработку и не сохранять дополнительные копии текста.
- **Kubectl snippets:** добавить готовые snippets с выбором namespace/resource через `options=`; существующие OptionChips остаются UI. Выбор статический и не запускает `kubectl` при открытии snippet.
- **Terminal-aware Recent:** при активном Terminal команды с явными DevOps-категориями получают приоритет в Recent. Категория задаётся метаданными, а не выводится из ID или имени команды.

### OMP handoff: KubeLens

Подхватить отдельный KubeLens extension как read-only интерфейс для pod, событий и диагностики. Переносить исходники из незакоммиченного checkout только после аудита. Вызовы `kubectl` используют argv-массивы без shell interpolation, корректно сохраняют полные имена context (включая EKS ARN), используют явные context/namespace и не предлагают restart `deployment/<pod-name>`. Мутирующие действия не включать. Диагностические правила покрыть fixtures; реальные kubeconfig и кластер для тестов не требуются.

## Общая безопасность и ошибки

- Все процессы запускаются с проверенным executable и позиционным массивом аргументов.
- Production guard находится в service/model policy и применяется при каждом мутирующем вызове.
- Кластерные, контейнерные, Helm и Ansible изменения требуют явного подтверждения. Режим по умолчанию не выполняет Ansible playbook без `--check --diff`.
- Секреты не сохраняются в настройках, логах, UI state или истории. Vault значения доступны только для копирования через внутренний clipboard path, исключённый из истории Tinycast.
- Отсутствующий CLI, некорректный config, отказ в доступе, ненулевой exit code и отмена имеют разные сообщения. Долгие процессы всегда имеют видимую остановку.
- Не устанавливать CLI и не менять глобальный kube context автоматически.

## Проверка

- Unit tests: YAML/JSON границы, cron поля, kubeconfig merge/parser, prod policy, inventory parsing и модели Workflows.
- Fake executable tests: точные аргументы kubectl/Ansible/Docker/Helm/Vault/SSH/glab; подтвердить отсутствие shell interpolation и production guard.
- Runtime tests: stdout/stderr events, stdin, exit/error, cancel, app/extension shutdown и ограничение очереди.
- Shipped Swift sources компилируются отдельными standalone harnesses через `Scripts/run-tests.sh`; XCTest target не добавляется.
- Build macOS app и все относящиеся к изменениям тесты. Для ручной проверки нужны только локальные fake configs; реальные кластеры, Vault и Jira не требуются.

## Этапы реализации

1. Quick Actions YAML/cron и Kube Context Guard.
2. Git Worktrees и Jira Key Actions.
3. Pods/Logs и port-forward manager.
4. Ansible Runner.
5. Compose, Helm, Vault и SSH extensions.
6. Streaming spawn и `menu-bar` extension lifecycle.
7. Custom Commands в Workflows; 11.9 интеграции и KubeLens handoff; полная сборка и интеграционная проверка.

После проверки изменений отправить DevOps-изменения отдельной веткой в `1tuz/tinycast`. Не включать несвязанные изменения рабочего дерева и не обновлять `main`.
